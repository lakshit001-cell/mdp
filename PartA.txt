In Part A, we model the sequential decision-making problem as a Markov Decision Process and determine the optimal policy using in-place value Iteration until convergence, defined as the maximum absolute value change across all states falling below epsilon. The initialization routine parses the layout and probability files to extract grid geometry, movement restrictions, rewards, transition uncertainties, and the start state, aligning coordinates with the origin at the bottom-left corner. Instead of computing values over the intractable full Cartesian product of all grid cells and entities, our approach restricts computation strictly to reachable configurations. The entire algorithm executes in two distinct phases: forward state-space discovery with transition compilation, followed by value iteration and policy extraction.

Phase 1 constructs the reachable state space and precomputes transition dynamics using a breadth-first search implemented via a queue. Starting from the initial state, value_iteration_setup systematically evaluates the four actions using compute_transitions. For any state-action pair, compute_transitions calculates the marginal movement distributions for the ship and both independent pirates via state_changes, enforcing grid boundaries and obstacle constraints such that attempted moves into land or outside designated pirate zones result in the entity remaining stationary. It then takes the Cartesian product of these outcomes to derive the joint next-state distribution, accumulating probabilities for identical resulting configurations. Immediate step costs, pirate collision penalties, treasure reward, and fort rewards are incorporated into each transition by use of if checks. States where the ship collides with a pirate or reaches the fort are flagged as terminal and added to the state list, but excluded from the queue to terminate expansion and end the episode.
Phase 2 performs in-place (dynamic programming) Value Iteration directly across the discovered non-terminal states, with all initial valuations set to zero. During each sweep, the algorithm computes Bellman updates by evaluating the expected return across all four actions using the precomputed transition stored in transition cache. Because terminal states possess valuation of zero, transitions entering termination contribute purely through their immediate reward, completely avoiding unnecessary recursive lookups. Overwriting state values immediately within the same for-loop accelerates reward propagation across adjacent grid cells compared to standard bellman updates. To maximize runtime efficiency and eliminate redundant passes over memory, policy extraction is done within the value iteration loop: the action index with the maximal value is recorded into the policy dictionary whenever a superior value is found and after all actions are checked, the state policy is set to the best action. A loop condition monitors elapsed time, ensuring clean termination before allocated limits expire.
Finally, during evaluation, the get_action function queries the precomputed policy table using the environment's current observation tuple and returns the optimal discrete action in constant time.
